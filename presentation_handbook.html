Chapter 2: What is Git?

The Local Engine • Distributed Version Control System (DVCS)

Slide 2 of 7

📖 Official Definition

Git is a free, open-source Distributed Version Control System (DVCS) installed directly on your local computer. It tracks every single character modification across your entire codebase over time.

⚡ The 3 Superpowers of Local Git

⏱️ Pixel-Perfect Change Tracking

Git records who made changes, exactly which lines were added or deleted, and when. You never have to guess what broke your build.

🧪 Fearless Experimentation

Create an isolated parallel branch to test a crazy new algorithm or library. If it fails, delete the branch with zero impact on your working code.

⏳ Instant Time Travel (True Undo)

Made a catastrophic mistake? Git lets you revert a single file or your entire repository back to any previous commit in milliseconds.

⚙️ The 3 States of Git (Under the Hood)

Local Workspace

1. Working Directory

Untracked / Modified

Your actual project files where you write code, edit CSS, and test in your browser.

Photo Lineup

2. Staging Area (Index)

git add

The preparation stage. Like lining up people for a group photograph before taking the snapshot.

Permanent Vault

3. Local Git Repository

git commit -m "..."

The permanent record. The snapshot is stamped into the `.git` database with a cryptographic SHA hash.

Terminal • Real Lifecycle Sequence
# 1. Initialize a new local Git repository $ git init Initialized empty Git repository in /workspace/my-app/.git/ # 2. Check repository status $ git status Untracked files: (use "git add <file>..." to include in what will be committed) index.html app.js # 3. Stage changes for the snapshot $ git add . # 4. Save permanent snapshot with a clear message $ git commit -m "feat: setup initial navbar and responsive grid layout" [main (root-commit) 4e82b19] feat: setup initial navbar and responsive grid layout 2 files changed, 142 insertions(+)
Command Syntax Action & Description
git init Creates the hidden `.git` folder that holds your local repository database.
git status Shows modified files, staged files, and untracked files in your working directory.
git add . Stages all new and modified files into the preparation index for the next commit.
git commit -m "msg" Permanently records the staged changes as a new commit node in history.
git restore <file> Discards local changes in working directory, reverting back to the last commit.

Chapter 3: What is GitHub?

The Cloud Collaboration Hub • Where Developers Build Together

Slide 3 of 7

📖 Official Definition

GitHub is a cloud-based hosting platform built for software developers. It hosts your remote Git repositories online, providing team collaboration tools, issue tracking, automated CI/CD pipelines, and your public engineering portfolio.

🌟 Why GitHub is Vital for Student Developers

🛡️ Unbreakable Cloud Backup

Your code is securely stored across worldwide data centers. Stolen laptop, broken SSD, or coffee spill? Run `git clone` on any machine and resume working in 60 seconds.

🤝 Frictionless Team Collaboration

Multiple developers work simultaneously on different branches. GitHub handles Pull Requests, inline code review discussions, and merges without stepping on toes.

💼 Your Living Developer Resume

Tech recruiters value a link to your GitHub profile more than an inflated resume. It shows real proof that you write clean code, write documentation, and contribute.

🚀 Free Hosting with GitHub Pages

You can host your portfolio websites, documentation, and web apps directly from a repository for free under `<username>.github.io`.

🎁 🎓 The GitHub Student Developer Pack:

As a verified student, you get free GitHub Copilot (AI pair programmer), free domains, cloud credits on Azure & DigitalOcean, and premium developer tools valued at over $200,000!

Chapter 5: Essential Vocabulary

The 8 Industry Power Words Every Developer Must Know

Slide 5 of 7
🔄 The 3-Phase Teamwork Lifecycle: • Phase A: Project Setup (Clone or Fork): Get the code onto your local machine with full history. • Phase B: Daily Feature Work (Branch ➡️ Add ➡️ Commit): Isolate your feature, stage atomic changes, and create checkpoints. • Phase C: Collaboration & Release (Pull ➡️ Push ➡️ Pull Request): Stay in sync with teammates and submit code for peer review.

📚 The 8 Power Words Reference

Repository (Repo) The Vault

Your project folder containing all code files, assets, and full cryptographic revision history.

git init
💡 Pro Tip: A repo can be local on your machine or remote on GitHub.
Commit The Snapshot

A permanent checkpoint of your project at an exact moment, tagged with a unique 40-character SHA hash.

git commit -m "feat: login form"
💡 Pro Tip: Write commit messages in present imperative tense ("Add feature", not "Added feature").
Push The Rocket

Uploading committed changes from your local repository up to a remote repository on GitHub.

git push origin main
💡 Pro Tip: Always test that your code compiles before pushing to a shared branch.
Pull The Tractor Beam

Downloading and integrating new updates from GitHub down into your local working directory.

git pull origin main
💡 Pro Tip: Run `git pull` every morning before you begin typing code to prevent merge conflicts!
Clone The Duplicator

Downloading an exact replica of an existing remote repository onto your computer for the first time.

git clone https://github.com/...
💡 Pro Tip: You only clone ONCE. Afterward, you use `git pull` to fetch updates.
Branch Parallel Universe

An isolated line of development. Build a feature safely without risking the stability of `main`.

git checkout -b feature-chat
💡 Pro Tip: Never code directly on the `main` branch in a team project!
Fork The Copycat

Creating your own personal copy of someone else's GitHub repository under your own account to freely modify.

Fork via GitHub Web UI
💡 Pro Tip: Open-source contributions always start by forking the original repository.
Pull Request (PR) The Peace Treaty

A proposal asking repository maintainers to review your branch changes and merge them into the main project.

Open via GitHub Web UI
💡 Pro Tip: PRs allow teammates to inspect code diffs and leave comments before anything breaks production.

Appendix: Audience Q&A Cheat Sheet

The Top 6 Real-World Questions Asked by Student Developers

Master Cheat Sheet
1. What happens if I accidentally commit my password or secret API key?
Answer: Git stores every past commit forever! Deleting the key in a new commit is NOT enough because anyone can inspect past commits in your git log. You must:
1. Immediately revoke and regenerate the API key online in your service dashboard.
2. Add .env and config files containing secrets to your .gitignore file.
3. Use tools like git filter-repo or BFG Repo-Cleaner to scrub the secret from all past commit history.
2. How do I fix a merge conflict if my code clashes with my partner?
Answer: Don't panic! A merge conflict just means you and your teammate edited the exact same line of code. Git pauses and writes conflict markers:
<<<<<<< HEAD (your local code), =======, and >>>>>>> partner-branch.
Open the file in VS Code, choose which version to accept (or combine both), save the file, run git add ., and finish with git commit. Member 2 demonstrates this in live action!
3. Is Git completely free? Does GitHub cost anything for students?
Answer: Git is 100% free and open-source under the GNU General Public License v2. GitHub is completely free for unlimited public and private repositories. Plus, as enrolled students, you qualify for the GitHub Student Developer Pack which unlocks free GitHub Copilot, domains, cloud credits, and over $200k+ in professional engineering tools!
4. Should I use the Terminal (CLI) or a GUI like GitHub Desktop / VS Code?
Answer: Start with the CLI (Terminal)! Practicing fundamental commands builds the true mental model of Git's 3 states. Once you grasp the underlying engine, visual tools in VS Code or GitHub Desktop become helpful accelerators rather than confusing black boxes.
5. What is the difference between "git fetch" and "git pull"?
Answer: git fetch downloads new commits and branches from GitHub into your local repository without modifying your working files (safe inspection). git pull runs both git fetch AND git merge automatically in a single step, updating your active branch immediately.
6. Why do some people say "master" branch and others say "main"?
Answer: Prior to October 2020, Git's default initial branch name was called master. In 2020, GitHub and the global open-source community transitioned to main as the standard default branch name for clarity and modern conventions. Both operate identically in the Git engine.
